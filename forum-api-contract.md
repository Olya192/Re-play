# Контракт: эмодзи-реакции на топик - договорённость с бэком

Что фронт ждёт от бэка по эмодзи-реакциям.
Реакции ставятся на **топик**. Покрывает TASK-50 (эмодзи-бэк) со стороны контракта и TASK-49 (реакции, клиент).

Стек бэка по бэклогу: Postgres 12+, sequelize.

---

## Авторизация

Юзера опознаёт бэк (кука Практикума). Главноео, что на бэке есть сущность **User**, и в ответах реакций автор приходит к готовым - не надо никого дорезолвивать на фронте.

## Модель данных (только нужное для реакций)

### Reaction
| поле      | тип         | примечание                          |
|-----------|-------------|-------------------------------------|
| id        | int PK      |                                     |
| topicId   | int FK      | -> Topic.id                         |
| userId    | int FK      | -> User.id                          |
| emoji     | varchar(16) | юинкод-символ из списка разрешённых |
| createdAt |    |                                     |

- `UNIQUE (topicId, userId, emoji)` - один и тот же эмодзи от юзера ставится один раз (основа toggle)
- Индексы: `Reaction(topicId)`, `Reaction(userId)` (можно составной)

### Topic
| поле | тип    |
|------|--------|
| id   | int PK |
| ...  | ...    |

### User (displayName - показать при наведении на реакции)
| поле        | тип     |
|-------------|---------|
| id          | int PK  |
| displayName | varchar |
| ...         | ...     |

## Хранение эмодзи

- `emoji` - юникод-символ (👍, ❤️), не картинки и не справочник
- "вайтлист" - общий список у фронта и бэка. Бэк проверяет, что пришедший эмодзи есть в списке, фронт этим же списком рисует палитру выбора
- базоый набор (держим синхронно): 👍  ❤️  😂  😮  😢  🔥

---

## Использование реакций

- **Toggle** переключатель - повторная реакция тем же эмодзи снимает её. Дубли невозможны из-за `UNIQUE(topicId, userId, emoji)`
- Один пользвоатель может поставить несколько разных эмодзи на один топик
- Реакции отдаются агрегированно: по каждому эмодзи - счётчик и флаг "моя реакция"

```json
"reactions": [
  { "emoji": "👍", "count": 5, "reactedByMe": true },
  { "emoji": "🔥", "count": 2, "reactedByMe": false }
]
```

`reactedByMe` считает бэк по текущему юзеру.

## REST-контракт реакций

```
GET    /api/forum/topics/:topicId/reactions            -> { reactions: ReactionAgg[] }
POST   /api/forum/topics/:topicId/reactions
       body: { emoji }                                  -> { reactions: ReactionAgg[] }
DELETE /api/forum/topics/:topicId/reactions/:emoji      -> { reactions: ReactionAgg[] }
```

- **GET** - получить текущие реакции топика (для первичной загрузки/рефетча). Реакции также могут приходить полем `reactions` в ручке самого топика - тогда отдельный GET нужен только для обновления после toggle
- Все три ручки возвращают один и тот же формат `{ reactions: ReactionAgg[] }`, чтобы фронт после любого действия просто перерисовывал бар реакций

## DTO для фронта

```typescript
type ReactionAgg = {
  emoji: string;
  count: number;
  reactedByMe: boolean;
};
```

Если понадобится показывать, кто именно реагировал (при наведении), бэк может добавить в элемент список `users: { id: number; displayName: string }[]`.
